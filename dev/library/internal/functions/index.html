EMB.variables_flow_resource(m, ℒ::Vector{<:EMB.Link}, 𝒫::Vector{<:ResourcePooling}, 𝒯, modeltype::EnergyModel)

Define additional pressure-related variables for links if there are ResourcePressure in the system. For ResourcePooling blends, define flow_component variables on each blend-carrying link.

For the ResourcePooling dispatch, proportion_out[n, t, p] is also created for the nodes that track the blend composition explicitly, see blend_share_plan.

For the ResourcePressure dispatch, the following variables are created:

  • link_potential_in[l ∈ ℒ, 𝒯, inputs(l.to)] — inlet potential for each link (all links, all resources of the destination node).
  • link_potential_out[l ∈ ℒ, 𝒯, outputs(l.from)] — outlet potential for each link (all links, all resources of the source node).
  • has_flow[l ∈ ℒ_pressure, 𝒯] — binary; equals 1 when a link is active (carrying flow). Used as a big-M switch in pressure-balance and capacity constraints to deactivate idle links. Note: has_flow = 1 is not sufficient to guarantee actual flow — it is only a necessary condition.

The binary variable is declared only for ℒ_pressure — the subset of links carrying at least one CompoundResource (ResourcePressure or ResourcePooling{<:ResourcePressure}). Links that carry only non-pressure resources such as ResourceCarrier (e.g., Power) do not require pressure binaries and are excluded to keep the MINLP compact.

constraints_balance_pressure(m, l::EMB.Link, 𝒯, 𝒫::Vector{<:CompoundResource})

Set internal balance pressures between potential_in and potential_out in Nodes n and Links l`. The balance will depend on type of nodes:

  • For NetworkNode nodes, the inlet and outlet potentials are equal.
  • For Compressor nodes, the inlet potential is lower than or equal to the outlet potential.
  • For DeblendNode nodes, the Blend output equals the Blend input (no pressure drop through the separator); the extracted H₂ output pressure is unconstrained here.
  • For PoolingNode nodes, the inlet potential of all input resources is equal to the outlet potential of all output resources.
  • For Links, the inlet potential is higher than or equal to the outlet potential. if there is no flow through l, both potentials are set to zero.

Note: Sinks and Source nodes do not have internal pressure balances, as their potentials are only defined at inlet or outlet respectively.

EnergyModelsGasNetworks.constraints_pressure_couple — Function
constraints_pressure_couple(m, n::EMB.Source, ℒ, 𝒯, 𝒫::Vector{<:CompoundResource})
constraints_pressure_couple(m, n::EMB.NetworkNode, ℒ, 𝒯, 𝒫::Vector{<:CompoundResource})
constraints_pressure_couple(m, n::Compressor, ℒ, 𝒯, 𝒫::Vector{<:CompoundResource})
constraints_pressure_couple(m, n::Compressor, ℒ, 𝒯, 𝒫::Vector{<:ResourcePressure})
constraints_pressure_couple(m, n::PoolingNode, ℒ, 𝒯, 𝒫::Vector{<:CompoundResource})
constraints_pressure_couple(m, n::DiscretizedPoolingNode, ℒ, 𝒯, 𝒫::Vector{<:CompoundResource})
constraints_pressure_couple(m, n::TransitNode, ℒ, 𝒯, 𝒫::Vector{<:CompoundResource})
constraints_pressure_couple(m, n::EMB.Sink, ℒ, 𝒯, 𝒫::Vector{<:CompoundResource})

Constraints coupling node potentials to the potentials of their connected links.

Each dispatch sets the node's potential_in and potential_out equal (within a big-M relaxation) to the corresponding link_potential_out and link_potential_in of connected pressure-carrying links. The coupling logic varies by node type:

  • EMB.Source: outlet potential equals each outgoing link's inlet potential (equality, no big-M needed since sources always inject).
  • EMB.NetworkNode, PoolingNode, TransitNode, EMB.Sink: uses has_flow big-M for both the upper and lower bound on potential_in[n]. When has_flow=1, both bounds bind, forcing potential_in[n] = link_potential_out[l] for each active link. When multiple links are active, their outlet potentials are all forced equal to the node inlet potential — correct junction physics assuming pressure reduction valves reduce any higher-pressure incoming flows to the node pressure.
  • Compressor: same as NetworkNode, but incoming Power links are filtered out before applying any pressure coupling (pressure coupling applies only to the gas resource, not the power resource).

Link filtering

In all dispatches, ℒᵗᵒ and ℒᶠʳᵒᵐ are filtered to include only links that carry at least one CompoundResource. This excludes Power-only links (e.g., compressor power inputs, output links from unit-conversion nodes) which have no link_potential_* variables and whose has_flow binary is not declared.

Pressure coupling

For each active incoming link (has_flow=1), the node inlet potential is bounded above by the link outlet potential via a has_flow-gated big-M constraint:

potential_in[n] ≤ link_potential_out[l] + 1e4*(1 - has_flow[l])

When has_flow=1 this forces potential_in[n] ≤ link_potential_out[l]. When has_flow=0 the bound is inactive. With multiple active incoming links the node inlet potential is bounded above by the minimum of all active link outlet potentials. The optimizer naturally drives the node pressure up to that minimum (to maximise downstream flow capacity), giving "lowest incoming pressure" semantics without a separate lower bound constraint.

No explicit lower bound is added for potential_in[n] from incoming links; the lower bound comes from downstream constraints (Weymouth flow requirements, MinPressureData).

constraints_pressure_couple(m, n::Compressor, ℒ, 𝒯, 𝒫::Vector{<:ResourcePressure})

Pressure coupling for a Compressor carrying a pure ResourcePressure gas (e.g. pure H₂, no blending). Mirrors the CompoundResource dispatch but filters for ResourcePressure links, excluding Power-only links that carry no pressure potential.

Enforces:

  • potential_in[n] ≤ link_potential_out[l_to] + BigM×(1−has_flow[l_to]) (inlet coupling)

EnergyModelsGasNetworks.constraints_flow_pressure — Function
constraints_flow_pressure(m, l::EMB.Link, 𝒯, 𝒫::Vector{<:ResourcePressure})
constraints_flow_pressure(m, l::EMB.Link, 𝒯, 𝒫::Vector{<:ResourcePooling{<:ResourcePressure}})

constraints_flow_pressure(m, l::EMB.Direct, 𝒯, 𝒫::Vector)

Set Weymouth constraints in link l, calculating the flow based on the pressure difference between inlet and outlet.

The Weymouth equation is approximated using the first-order Taylor expansion when the resource is a ResourcePressure. For a ResourcePooling of ResourcePressure sub-resources (blend links), a Piecewise Affine Approximation (PWA) in (p_in, p_out, proportion_H2) is used when a BlendData object is attached to the link. If no BlendData is present — for example when blend: nothing is set in YAML for a link that still carries a blend resource due to its node types — the function falls back to the 2D Taylor approximation at the reference (pure-component) composition encoded in PressureLinkData. This fallback is conservative: it uses the capacity at zero H₂ fraction, which is the minimum possible capacity (since adding H₂ lightens the gas and increases throughput).

No-op methods are defined for EMB.Direct links and plain Resource vectors where no Weymouth constraint is needed.

EnergyModelsGasNetworks.blend_share_plan — Function
blend_share_plan(𝒩, ℒ, 𝒫)

Decide which nodes track the blend composition explicitly with proportion_out.

The component flows on the links give the composition wherever blend mixes, so a share is only needed where a composition must be shared or read:

  • Composition sources (_is_composition_source): pooling nodes and blend storages in mode :prescribed or :fully_mixed, whose outflows all carry the composition of the node.
  • Weymouth pipes with BlendLinkData, whose PWA depends on the share of the tracked resource. The share is read from
    1. the inflow node, if it is a composition source, or else
    2. the first pooling node downstream, if the pipe is its only blend inflow, possibly through passthrough nodes with a single blend inflow and outflow. The composition is then the same along the whole path. Or else
    3. the inflow node, if all gas reaching it comes from composition sources through passthrough nodes, which then copy the share (see _constraints_blend_passthrough). The copy requires simultaneously active inflows of these nodes to have the same composition.

All other nodes, e.g. sinks, merges and passthrough nodes off such paths, only balance the component flows. A pipe without a share raises an ArgumentError.

Returns a NamedTuple with

  • provenance: for each blend, the classification of each node as proportion-capable (_PROPORTION_CAPABLE), component-flow-only (_COMPONENT_FLOW_ONLY) or both,
  • share_nodes: the nodes with proportion_out,
  • copy_nodes: for each blend, the passthrough nodes copying the share from upstream,
  • pwa_reader: for each (link, blend) pair with BlendLinkData, the node whose share the PWA uses.

EnergyModelsGasNetworks.get_pwa — Function
get_pwa(data_pressure::PressureLinkData, data_blend::BlendData, optimizer; resolution_prop=0.01)
get_pwa(l::EMB.Link, optimizer; resolution_prop=0.01)

Generate or retrieve the cached PWA (piecewise-affine approximation) of the Weymouth flow equation for a link with pressure and blending data.

The approximation is a Concave piecewise-affine function of three inputs: (p_in, p_out, proportion_tracked). It is generated by fitting planes to exact Weymouth evaluations on a pressure grid, with zero-flow anchor points at (0, 0, α) added to suppress infeasible positive intercepts.

Results are cached to a JSON file via the Scratch.jl scratch space (keyed on the fit parameters). See get_input_fn, read_from_json, and write_to_json.

The fit is seeded from the cache key, so the same data gives the same PWA in every process. Fitted and cached PWAs are checked with _pwa_fit_ok. A fit that underestimates the exact flow by more than 10 % of the maximum flow is refitted (up to _PWA_FIT_ATTEMPTS times, with a different seed each time) and never cached; if no attempt passes, an error is thrown. An ArgumentError is thrown if the pressure step (see set_step_pressure!) leaves fewer than three pressure levels in the range of the link.

If get_clamp_pwa_intercepts returns true (the default), plane intercepts are clamped via _clamp_pwa_intercepts after fitting to ensure feasibility on inactive reverse links.

EnergyModelsGasNetworks._clamp_pwa_intercepts — Function
_clamp_pwa_intercepts(pwa::PWAFunc{Concave, D}) where {D}

Return a copy of pwa with all plane intercepts clamped to β ≤ 0.

For a concave PWA, the per-plane constraint added by PiecewiseAffineApprox.constr is:

z ≤ -dot(plane.α, x) - plane.β

At x = (0, 0, 0) (link potentials forced to zero by constraints_balance_pressure when a reverse link is inactive): z ≤ -plane.β. With z = 0 (no flow on the inactive link), this becomes 0 ≤ -plane.β. If any plane has plane.β > 0 due to extrapolation outside the fitting domain, this constraint is infeasible.

Clamping sets β_k ← min(0, β_k) for each plane. This:

  • Makes 0 ≤ -β_k always satisfiable (since -β_k ≥ 0 after clamping).
  • Preserves the outer approximation: decreasing β_k increases -β_k, loosening the upper bound and keeping approx(x) ≥ f(x) on the fitting domain.

Called by get_pwa when get_clamp_pwa_intercepts() returns true (the default). Use set_clamp_pwa_intercepts! to control this behaviour.

EnergyModelsGasNetworks._constraints_blend_passthrough — Function
_constraints_blend_passthrough(m, n, ℒ, 𝒯, 𝒫)

Linear proportion passthrough for nodes that carry blend unchanged (no injection). Only the passthrough nodes that blend_share_plan selects to copy the share, i.e. those between composition sources and a link with BlendLinkData, get these constraints.

Single-link case (no circularity possible): When a node has exactly one incoming blend link, a hard equality is used: proportionout[n, t, p] == proportionout[upstream, t, p]

Multi-link case (bidirectional / cyclic networks): When a node has two or more incoming blend links, a big-M formulation conditioned on has_flow is used instead of a hard equality. For each incoming link l_up:

proportion_out[n, t, p] - proportion_out[upstream, t, p] ∈ [-(1 - has_flow), (1 - has_flow)]

When has_flow[l_up, t] = 1 (link is active) this collapses to a hard equality, propagating the upstream composition. When has_flow[l_up, t] = 0 (link is inactive) the constraint is trivially satisfied and proportion_out[n] is not pinned to that (inactive) upstream.

This matters in bidirectional networks: a pair {A→B, B→A} carries has_flow[A→B] + has_flow[B→A] ≤ 1, guaranteeing at most one direction is active. Without conditioning, iterating both links would add proportion[n] = proportion[A] and proportion[n] = proportion[B] — contradictory if A and B carry different compositions, and circular (free) if they share the same cycle. Conditioning on has_flow breaks the contradiction: only the active-direction link constrains the proportion.

proportion_out ∈ [0, 1], so M = 1 is the tightest valid big-M coefficient.

Fallback: if has_flow is not in the model (networks without ResourcePressure), hard equalities are used in all cases — safe for the acyclic / unidirectional topologies those models represent.

A copy node may have several simultaneously active inflows (a merge). The constraints then require their compositions to be equal, which restricts the solution; place a pooling node at such merges instead.

EnergyModelsGasNetworks._constraints_dpn_bigm — Function
_constraints_dpn_bigm(m, n, ℒ, 𝒯, 𝒫, K, max_prop; log_encoding=false)

BigM MILP formulation for DiscretizedPoolingNode using the composition approach.

Composition Approach

Rather than per-link split fractions, a SINGLE set of binary variables selects the composition (proportion) level for the pooling node at each time step. This is shared across ALL outgoing links — the same composition applies to all downstream pipelines, which is the physical interpretation of a pooling node.

max_prop limits the proportion axis to [0, max_prop]. All K levels span this range, so every level is within the feasible H₂ fraction bound. With max_prop = 1.0 (default), levels span [0%, 100%]; with max_prop = 0.20, they span [0%, 20%].

Standard BigM (log_encoding = false):

  • K binary variables δ[t, k] per time step, exactly one active: Σ_k δ[t,k] = 1
  • K discrete levels α_k = (k-1)/(K-1) × max_prop for k=1..K
  • proportion_out[n, t, sub[1]] = Σ_k α_k · δ[t,k] ← linear!
  • proportion_out[n, t, sub[2]] = 1 - proportion_out[n, t, sub[1]]
  • For each outgoing link l and level k:
    • w[l,t,k] approximates δ[t,k] · link_in[l,t,blend] via BigM:
      • w ≤ F_max · δ[t,k]
      • w ≥ link_in - F_max · (1 - δ[t,k])
      • 0 ≤ w ≤ link_in
    • flow_component[l,t,sub[1]] = Σ_k α_k · w[l,t,k]
    • flow_component[l,t,sub[2]] = link_in[l,t,blend] - flow_component[l,t,sub[1]]

Logarithmic BigM (log_encoding = true):

  • n_bits = ⌈log₂(K)⌉ binary variables b[t, j] per time step
  • Actual levels: K_actual = 2^n_bits (rounded up from K)
  • Level index: k = Σ_j 2^(j-1) · b[t,j] (binary encoding)
  • proportion_out[n, t, sub[1]] = Σ_j 2^(j-1)/(K_actual-1) × max_prop · b[t,j] ← linear!
  • For each outgoing link l and bit j:
    • w_j[l,t] approximates b[t,j] · link_in[l,t,blend] via BigM
    • flow_component[l,t,sub[1]] = Σ_j 2^(j-1)/(K_actual-1) × max_prop · w_j[l,t]

Why This Is Equivalent to the User's N-1 Split Fraction Description

For a 2-component blend and N outgoing links: the composition approach uses ONE binary set (not N-1) because all N links share the same pooled composition. The N-th link's component flows are then inferred by the node mass balance (already a linear constraint).

Restriction

Currently supports only 2-component blends (M = 2). Asserts length(sub) == 2.

EnergyModelsGasNetworks._constraints_unit_conversion_blend_lhv — Function
_constraints_unit_conversion_blend_lhv(m, 𝒩, ℒ, 𝒯, 𝒫)

Add the linearised FlowToEnergyData conversion constraint for every UnitConversion node whose input is a ResourcePooling blend and whose FlowToEnergyData specifies per-sub-resource LHV values.

This must run after link variables (flow_component) have been declared, which is why it cannot be placed in constraints_ext_data (the node constraint phase).

For each qualifying node the constraint added is:

flow_out[n, t, p_out] == Σ_{l_in} Σ_sub  lhv_sub × flow_component[l_in, t, sub]

which is linear because flow_component[l_in, t, sub] is an explicit variable (it already encodes proportion_out × flow_in).

Outputs that appear as keys in an EmissionsConversionData on the same node are skipped here — they are handled separately by _constraints_unit_conversion_co2_output.

EnergyModelsGasNetworks._constraints_unit_conversion_co2_output — Function
_constraints_unit_conversion_co2_output(m, 𝒩, ℒ, 𝒯, 𝒫)

Add the linearised CO₂ emission output constraint for every UnitConversion node that has an EmissionsConversionData attached and a blend (ResourcePooling) input.

Must run after flow_component link variables exist (i.e., in the deferred blend constraint phase, called from constraints_component_blend).

For each qualifying node and each resource p whose value appears as an output in the node's output dict AND whose key is in EmissionsConversionData.co2_intensity, the constraint is:

flow_out[n, t, p] == Σ_{l_in} Σ_sub  co2_intensity[sub] × flow_component[l_in, t, sub]

Units: flow_component [MSm³/d], co2_intensity [tCO₂/MSm³] → flow_out [tCO₂/d].

EnergyModelsGasNetworks._constraints_proportion_normalisation — Function
_constraints_proportion_normalisation(m, n, sub, ℒ_out, 𝒯)

Require the proportions proportion_out[n, t, p] of the sub-resources sub to sum to 1.

When has_flow variables are present (pressure networks with ZeroDrop / Pipeline links), a conditional big-M formulation is used:

Σ_p proportion_out[n, t, p] ≤ 1
Σ_p proportion_out[n, t, p] ≥ has_flow[l, t]   for each outgoing blend link l ∈ ℒ_out

This relaxes the equality when no gas flows (has_flow = 0), allowing the NLP relaxation to set proportion_out = 0. Without it, a node that only receives a single sub-resource (e.g. a pure-H₂ electrolyser) would propagate proportion_out[H2] = 1.0 even at zero flow, violating quality bounds at downstream consumers and causing the NLP relaxation used by MINLP solvers to report spurious local infeasibility. In the MILP (has_flow ∈ {0,1}), the two constraints collapse to the equality whenever an outgoing blend link is active.

EnergyModelsGasNetworks._constraints_passthrough_single_outflow — Function
_constraints_passthrough_single_outflow(m, 𝒩, ℒ, 𝒯, 𝒫)

For every passthrough node with several outgoing links carrying a blend, allow at most one of them to be active in each period:

Σ_{l_out} has_flow[l_out, t] ≤ 1

Flow on a pressure link forces has_flow = 1 (constraints_flow_capacity), so the blend leaves the node through a single link, whose component flows equal those entering the node. This keeps the passthrough linear while allowing bidirectional pipelines, where a junction has an outgoing link towards each neighbour but only one carries flow.

EnergyModelsGasNetworks._pwa_flow_bound — Function
_pwa_flow_bound(pwa::PWAFunc)

Return a finite upper bound on the flow allowed by the concave PWA pwa over the box p_in, p_out ∈ [0, 1e4] (the big-M bound on link potentials in constraints_balance_pressure) and proportion ∈ [0, 1].

Each plane k gives z ≤ -α_k⋅x - β_k. The maximum of an affine function over a box lies at a corner, and the PWA lies below every plane, so min_k max_corners (-α_k⋅x - β_k) is a valid bound.
